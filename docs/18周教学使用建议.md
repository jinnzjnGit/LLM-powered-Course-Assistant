# 18周教学使用建议

本项目作为《AI大模型应用与工程实践》的贯穿案例，共18个有效教学周、每周4课时。按现有三模块七项目安排，总计72学时，理论24、实践48。下表是实训任务安排建议，不替代学校正式授课计划；节假日另按校历处理。

| 周 | 对应项目 | 学生任务与验收成果 |
|---|---|---|
| 1 | 选题与需求分析 | 体验资料答疑，记录真实学习痛点；说清目标用户与问题 |
| 2 | 选题与需求分析 | 提交功能清单、草图、分工和三个可检查的验收条件 |
| 3 | 设计与技术选型 | 比较界面、模型、资料和存储方案，说明选择理由 |
| 4 | 设计与技术选型 | 画数据流程图，说明PDF、片段、题目、提交、记录之间的关系 |
| 5 | 环境准备与原型验证 | 本机重建环境并完成检查，学习.env和首次模型调用 |
| 6 | 环境准备与原型验证 | 修改独立提示词，记录同一问题的两组输出及差异 |
| 7 | 核心功能开发 | 阅读materials和retrieval，用自己的PDF检查解析与分段 |
| 8 | 核心功能开发 | 跑通带出处问答和多轮上下文，演示清空与资料不足场景 |
| 9 | 核心功能开发 | 测试BM25召回；用教师提供的最小向量检索示例做对照，提交记录 |
| 10 | 核心功能开发 | 调整交互页面并接入总结或测验，提交功能版 |
| 11 | 集成、测试与简单部署 | 阅读validation，解释为什么不能相信模型JSON；补一个异常用例 |

| 17 | 优化与工程管理 | 完成使用手册、已知缺陷、贡献说明和交付目录 |
| 18 | 演示与评审 | 现场演示、解释一段代码、完成一个小修改并展示测试证据 |

## 分层任务

基础任务为PDF文本解析、检索问答、出处、交互界面和本地运行。OCR、测验批改和数据库由教师提供骨架，学生围绕数据流补充或修改。复习规划、混合检索、成本统计和自主工具调用作为提高任务。

当前仓库已经提供完整参考实现和测试，没有伪装成七套历史版本。授课时教师应按周发放对应模块的起始骨架与任务，避免第一周就要求学生阅读完整实现。向量检索示例尚需教师补充，不能把BM25当成已完成向量检索教学。

## 每次4课时的组织

按当周内容分配讲授与实训时间，整个学期合计满足24理论、48实践。每次实训保留“教师演示—学生修改—互查—提交证据”四个环节，不要求学生从零重写全部代码。Git提交、运行截图和测试记录应能对应学生实际修改。

建议用六类成果组织阶段验收：需求与设计、可运行原型、功能版、集成版、优化版、交付版。每组可以选不同课程资料或学习场景，但必须完成自己的修改和验证，不能仅换标题。

## 评价与交付

沿用课程标准：全过程表现20%、阶段项目40%、客观性考核10%、成果演示答辩30%。应用内AI练习评分不直接作为课程总成绩。

最终交付包括源代码、独立提示词、安装说明、测试记录、优化前后对照、演示材料和个人贡献说明。不得打包真实.env、学习数据库或.venv；使用有权分发的示例资料。每位学生至少解释一个函数，演示一个失败输入，并完成一个可验证的小修改。
